# Repair v4 实现与无费用验证

实现提交：`2291db8`、`fdc5d78`。入口配置 `repair-v4.json`，使用独立 `/tmp/graft-admission-v5-target` 构建。旧二进制、旧付费校准目录、暂停批次与账本均保留。

## 实现

- `replay_repair_attempts.py` 按 generation 中每次尝试绑定的计划检查全部响应，校验原目标身份和封存源码。重规划后的响应不再错误配对初始计划。新增回放和人工正例工具同时禁止模型客户端和 HTTP 发送。
- 签名记录真实参数数量和 receiver 位置；所属 owner 不等于 receiver。旧计划可从冻结 rustdoc 恢复分类。rustdoc 身份使用与 Rust 导入器一致的规范 JSON SHA，另保留原文件 hash。
- `model_source.py` 保留原响应及提取记录。新配置先经 Rust parser 确认纯源码；失败后仅提取唯一完整 Rust 块，再执行全部合同/编译/运行检查。提取不会替模型改代码。
- `repair_context.py` 和新版本提示生成具体修复任务：空输入安全读取、借用前计算、避免 shadow、前置 Result 合法参数、真实对象准备、当前计划构造器。提示包含活动计划 hash、调用列表和失败输入；可信 Extract 标记区分生产者分支拒绝。
- 当前计划和安全 helper 文档重新检索，使用短签名与明确截断的说明，避免长目标文档挤掉 grow/push_field/alloc_slice_copy。保留文档 2600 字节、提示规则 2200 字节、诊断 1400 字节、总提示 14000 字节及既有费用上限。
- 新增 csv 记录/Position/Option<Position>、Bump 资源值、Option<primitive> 的值观测。所有摘要实际计算均位于诊断开关内；普通环境清除诊断标记，正式任务禁止携带这些标记。只求值一次实际参数，不观察地址。
- 记录解析 token key、重复响应、重复失败类别和源码处理耗时。token key 保留字符串字面量；不声称一般语义等价。第二次失败仍终止，不增加调用次数。
